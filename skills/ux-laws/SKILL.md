# UX laws

Match the decision to the lines below. Before you apply or cite a law, read `references/<name>.md` in full. In the reply, name each law that shaped a decision and the specific choice it changed.

**Interaction**

- `fitts-law`: sizing or placing a control → bigger and closer is faster; size by hit area, not icon.
- `hicks-law`: too many simultaneous choices → fewer options, or stage them.
- `millers-law`: grouping fields, menus or data → chunk into groups of about four.
- `doherty-threshold`: perceived slowness → respond within 400ms, or show progress.
- `jakobs-law`: inventing a pattern → match conventions users already know.
- `teslers-law`: deciding who absorbs complexity → the system, not the user, where possible.
- `serial-position-effect`: ordering a list or nav → most important first and last.
- `peak-end-rule`: designing a flow's moments → polish the most intense step and the ending.
- `zeigarnik-effect`: progress, multi-step tasks → make incomplete work visible and resumable.

**Visual**

- `law-of-proximity`: spacing → closeness groups more strongly than any other cue.
- `law-of-common-region`: containers, cards, borders → a shared region groups regardless of spacing.
- `law-of-similarity`: styling related items → shared colour, shape or size signals one category.
- `law-of-continuity`: alignment, step sequences → the eye follows unbroken paths.
- `law-of-closure`: reducing visual weight → the eye completes implied shapes.
- `law-of-figure-ground`: layering, modals, overlays → make foreground and background unambiguous.
- `von-restorff-effect`: emphasising one item → the one that differs is remembered; use it sparingly.
- `aesthetic-usability`: polish vs function → polished interfaces are perceived as more usable, which can mask real problems in testing.
